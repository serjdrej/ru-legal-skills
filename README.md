# ru-legal-skills

NDA само по себе не создаёт охраняемую коммерческую тайну по российскому
праву — без мер режима коммерческой тайны (98-ФЗ) оно ничего не защищает.
Это самая частая ошибка при переносе англо-американских шаблонов в
российскую практику. Готовых импортируемых скиллов под это не нашлось —
`anthropics/claude-for-legal` не подошёл: 0 из 151 его скилла оказались
переносимы (машинерия — `.claude`-запись, коннекторы, шедулеры — под запретом
в проекте-источнике). Поэтому эта семья написана с нуля.

Плагин-маркетплейс для Claude Code и Codex: три навыка по российскому праву
и российским стандартам (ГОСТ), собранные основателем, который сам себе и
юрист, и инженер — каждый навык покрывает область, где ему приходится
действовать самостоятельно, без штатного специалиста. Пример дисциплины,
которую это даёт: в давящем тестовом сценарии без скилла модель уверенно
назвала неверно процитированный срок уведомления по 152-ФЗ; с загруженным
скиллом — тот же вопрос под тем же давлением дал явную оговорку «не
подтверждено, перепроверьте» вместо уверенного числа. Подробности и другие
такие сравнения — в истории сборки каждого скилла (`docs/` соответствующего
репозитория).

**Каждый содержательный результат — черновик для проверки квалифицированным
специалистом (юристом, патентным поверенным, инженером по сертификации — по
профилю навыка), а не готовый к подаче документ или консультация.**

## Установка

**Claude Code:**

```
/plugin marketplace add serjdrej/ru-legal-skills
```

Затем для каждого нужного навыка:

```
/plugin install gost-ed-mashiny@ru-legal-skills
/plugin install legal-ru@ru-legal-skills
/plugin install patent-ru@ru-legal-skills
```

**Codex CLI:**

```
codex plugin marketplace add serjdrej/ru-legal-skills
```

Затем для каждого нужного навыка:

```
codex plugin add gost-ed-mashiny@ru-legal-skills
codex plugin add legal-ru@ru-legal-skills
codex plugin add patent-ru@ru-legal-skills
```

Обе команды читают один и тот же `.claude-plugin/marketplace.json` — отдельного
манифеста для Codex не нужно. Источник каждого плагина — форма `"url"`
(корень git-репозитория, закреплённый на точном коммите через `ref`), а не
специфичная для Claude Code форма `"github"` — она уже проверена вживую на
обоих рантаймах.

## Adding a new skill

Этот маркетплейс не хранит содержимое навыков — каждый плагин живёт в своём
собственном репозитории, на который `marketplace.json` только ссылается.
Новый плагин — это любой самостоятельный репозиторий той же формы, что и три
перечисленных выше: корневой `SKILL.md` с валидным frontmatter, `LICENSE`,
`README.md`, опционально `.claude-plugin/plugin.json`, и `references/` для
содержательного материала.

Чтобы добавить такой репозиторий в этот маркетплейс, нужна ровно одна новая
запись в массиве `plugins` файла `.claude-plugin/marketplace.json` — с полями
`name`, `description` (взятым из `SKILL.md` этого репозитория), `author`,
`category` и `source`:
```json
"source": {
  "source": "url",
  "url": "https://github.com/<owner>/<repo>.git",
  "ref": "<закреплённый SHA коммита>"
}
```
(не `"source": "github"` — эта форма распознаётся только Claude Code, Codex её
молча пропускает; `"url"` работает в обоих.) Больше ничего в этом репозитории
менять не нужно.

Если новый навык цитирует нормы (законы, ГОСТы, техрегламенты), прочитайте
[docs/norms-verification-convention.md](docs/norms-verification-convention.md)
перед тем, как писать его `references/norms-registry*.md` и скрипт
перепроверки — это общая для трёх существующих навыков конвенция оформления
реестра норм, выведенная из них, а не независимая от них схема.
