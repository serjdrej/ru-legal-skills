# ЧЕРНОВИК: слой роста для семьи ru-legal-skills

**Статус: проект для решения владельца. Не реализовано, ничего в скиллах не
изменено, ничего не закоммичено.** Написано 2026-09-14.

> **Пометка 2026-09-19.** §6 опирается на редакцию §7 конвенции до
> 2026-09-18. Различение подвидов AD HOC живо, но привязка «скилл → подвид»
> устарела: граница проходит по тому, какой **скрипт** дал находку. См.
> действующую редакцию `docs/norms-verification-convention.md` §7.

Задача: скиллы из маркетплейса — неизменяемая база; на машине пользователя
они должны накапливать собственное знание во время работы. Каждый скилл
независимо, по одной общей конвенции.

## 0. Краткий ответ, до деталей

Рекомендация в одну строку: **строить одну полосу, а не две.**

- **Полоса B (рабочее знание из практики владельца)** — настоящая растущая
  база. Общая на всю семью, разложена по сущностям, читается через
  собственный индекс. Это единственная часть конструкции, которая создаёт
  ценность, которой нет ни в одном публичном источнике.
- **Полоса A (внешние факты о нормах)** — **не база знаний, а очередь на
  промоушен.** Никогда не читается как источник для ответа пользователю,
  никогда не цитируется. Только список «эту норму спрашивали N раз, живой
  поиск такого-то числа дал вот это, в реестр не внесена». Читает её ровно
  два потребителя: процедура обслуживания раз в месяц и фраза скиллу «ты уже
  это спрашивал».

Почему полоса A схлопывается до очереди — разбор в §6. Коротко: локальная
база норм дублирует `references/norms-registry*.md` с более слабым
провенансом, тащит за собой правило устаревания (§9 утверждений ведущей
сессии — верное), и её выигрыш («не искать второй раз») достигается
очередью на два порядка дешевле и без риска самоотравления.

Ответ на открытый вопрос (одна общая база B на проект или отдельная у
каждого скилла) — §5. Коротко: **общая, но с разбиением по сущностям, а не
по скиллам.**

Бюджет SKILL.md — **10 строк, жёсткий потолок 12**, обоснование в §8.

| 5 | Главный риск — самоотравление; писать только пришедшее извне модели | **Верно и это единственное правило, на котором держится вся конструкция.** Добавление: границу надо делать **проверяемой**, а не декларативной, иначе она держится на добросовестности агента в момент записи. Растущий блок в `SKILL.md` — постоянный налог на каждую активацию, независимо от того, объявлена экономия контекста целью или нет |

Значит запись в каталог вне рабочего каталога Codex будет заблокирована песочницей. Точная правка — §10 |

Ещё три факта, найденных попутно, не входящих в девять утверждений:

- `patent-ru` содержит каталог `.secrets/` с файлом `rospatent_key.enc`.
  `.gitignore` его закрывает полностью и с объяснением, `keystore.py`
  переносит ключ при первом запуске — то есть это остаток старой схемы,
  обработанный корректно. Но `docs/review-checklist.md` («No dot-prefixed
  path… anywhere») этому формально противоречит, как и `.claude-plugin/` в
  `gost-ed-mashiny`. Пункт чеклиста стоит уточнить отдельной правкой — к
  слою роста не относится, отмечаю чтобы не потерялось.
- Из четырёх плагинов `plugin.json` есть только у `gost-ed-mashiny`
  (`version: 1.0.0`). Как Claude Code выбирает имя версионного каталога для

  (каталог версионирован в любом случае), но если кто-то будет проверять
  экспериментально — начинать надо отсюда.
- Соглашение семьи `references/` = грузится агентом по требованию, `docs/`
  = для человека и сопровождающего, подтверждается раскладкой всех четырёх
  репозиториев. Слой роста должен в него лечь, а не рядом (§8).

## 2. Что это за конструкция, в одном абзаце

Вокруг каждого скилла появляется **одна пользовательская пристройка на
машину** — каталог простых markdown-файлов вне всех репозиториев и вне
каталогов установки. Скиллы читают из неё по индексу (прогрессивная выдача:
индекс → карточка), пишут в неё по узкому списку триггеров, и **никогда не
пишут туда то, что придумали сами**. Кода нет: ни скриптов, ни индексаторов,
ни эмбеддингов — только файловая конвенция и инструкции, поэтому она
одинаково работает в Claude Code, в Codex и в текстовом редакторе владельца.

## 3. Раскладка файлов

### 3.1 Корень

```
~/.ru-legal-skills/          ← Windows: C:\Users\<user>\.ru-legal-skills\
```

Переопределяется переменной окружения `RU_SKILLS_MEMORY`, если она задана и
указывает на существующий каталог.

Почему именно так:

- **Вне дерева плагина** — прямое следствие §1/#4. Прецедент и
  формулировку берём из `patent-ru/scripts/keystore.py`: расположение не
  зависит от того, куда и сколько раз установлен скилл.
- **`$HOME`, а не `%LOCALAPPDATA%`/`~/Library/Application Support`** —
  в отличие от зашифрованного ключа, эту базу владелец должен открывать,
  читать и править руками. Один путь на все три ОС = одна строка в
  `SKILL.md` без ветвления по платформам; `~` понимают и Bash, и
  PowerShell (`$HOME`).
- **Вне любого git-репозитория по умолчанию.** Это не стилистика: у этой
  семьи уже была утечка в историю GitHub, которая на 2026-09-14 не закрыта
  (`docs/PROJECT-JOURNAL.md`, круг 4 — GitHub отдаёт удалённые коммиты по
  прямому SHA). Карточки по контрагентам и живым спорам — ровно тот класс
  содержимого, который не должен иметь никакого пути в `git push`.

### 3.2 Дерево

```
~/.ru-legal-skills/
  README.md                  # что это, как править, как обнулить (пишет человек, один раз)
  PAUSED                     # необязательный файл-стоп: есть → читать можно, писать нельзя
  practice/                  # ПОЛОСА B — общая на всю семью
    INDEX.md                 # роутер: одна строка на карточку
    counterparties/<slug>.md # контрагенты: заказчики, подрядчики, ведомства, орган по сертификации
    matters/<slug>.md        # дела/проекты/заявки: один объект работы
    playbook/<slug>.md       # приёмы: формулировки и ходы, у которых есть наблюдаемый исход
  queue/                     # ПОЛОСА A — очередь на промоушен, по одному файлу на скилл
    legal-ru.md
    patent-ru.md
    gost-ed-mashiny.md
    arbitrazh-ru.md
  archive/                   # куда уезжает отменённое и протухшее. Агент НИКОГДА не удаляет, только переносит сюда
```

Полоса A — по одному **файлу** на скилл, не по каталогу: это список на
десятки строк, а не база. Если файл скилла перевалил за ~80 строк, это
сигнал не делить его, а сесть и внести накопленное в реестр.

### 3.3 Чего в этом дереве нет и не будет

Ни одного исполняемого файла, ни `.json`-индекса, ни `.lock`, ни базы.
Всё, что здесь лежит, читается глазами и правится в блокноте. Любой скрипт
здесь — это то, что надо будет портировать между рантаймами и чинить.

## 4. Форматы записи, готовые к копированию

### 4.1 Полоса B — карточка

Имя файла: `<slug>.md`, латиница/цифры/дефис, без пробелов и кириллицы
(чтобы путь одинаково жил в PowerShell, Bash и в git-репозитории, если
владелец однажды решит его туда положить).

```markdown
# ООО «Стройпоставка» — заказчик по подряду

- **id:** B-cp-strojpostavka
- **тип:** контрагент
- **скиллы:** legal-ru, arbitrazh-ru
- **создано:** 2026-09-14 · **последнее подтверждение:** 2026-09-14
- **проверка при записи:** норм не содержит; ПДн физлиц не содержит

## Что известно

- Источник: сказал пользователь, 2026-09-14 — на переговорах всегда
  требуют убрать п.7 (одностороннее подписание акта) и заменить на
  двусторонний с 10-дневным сроком возражений.
- Источник: документ пользователя `dogovor-2026-04.pdf`, 2026-09-14 —
  в подписанной редакции п.7 действительно в двусторонней формулировке.
- Источник: фактический исход, 2026-08-20 — оплата пришла на 41-й день
  при договорных 30; претензию не направляли.

## Чего это НЕ значит

- Три наблюдения, не закономерность. Не подставлять двустороннюю
  формулировку в новый договор по умолчанию — предложить и спросить.
- Ничего не говорит о том, что закон требует или разрешает по акту
  приёмки: это в `legal-ru/references/norms-registry-podryad.md`, здесь
  норм нет по определению.
```

Обязательные поля: `id`, `тип`, `скиллы`, обе даты, строка `проверка при
записи`. У **каждого** пункта в «Что известно» — свой префикс `Источник:` с
датой. Допустимых источников ровно четыре, других не бывает:

| Источник | Формулировка |
|---|---|
| Сказал пользователь | `Источник: сказал пользователь, <ГГГГ-ММ-ДД>` |
| Документ, который дал пользователь | `Источник: документ пользователя \`<имя файла>\`, <ГГГГ-ММ-ДД>` |
| Реальный исход | `Источник: фактический исход, <ГГГГ-ММ-ДД>` |
| Вывод запущенного скрипта/живого запроса | `Источник: вывод \`<точная команда>\`, <ГГГГ-ММ-ДД>` |

Пятого варианта нет, и вывод самой модели в этот список не входит — это и
есть механическая форма правила из §1/#5. Пункт без валидного префикса
`Источник:` при чтении **игнорируется**, а карточка показывается
пользователю как повреждённая.

Раздел «Чего это НЕ значит» обязателен и не может быть пустым. Это
противоядие от режима отравления полосы B (§1/#6): одно наблюдение,
записанное без границ, через месяц читается как правило.

### 4.2 Полоса B — строка индекса

`practice/INDEX.md` — таблица, одна строка на карточку, ≤140 символов:

```markdown
# Практика — индекс

Читать этот файл; карточку открывать только по совпадению ключевых слов.
Строка здесь — не знание, а адрес. Никогда не отвечать по строке индекса,
не открыв карточку.

| id | сущность | ключевые слова | скиллы | обновлено |
|---|---|---|---|---|
| B-cp-strojpostavka | ООО «Стройпоставка» | подряд, п.7, акт приёмки, просрочка оплаты | legal-ru, arbitrazh-ru | 2026-09-14 |
| B-pb-formula-uzel | приём: формула на узел | ФИПС, единство, независимый пункт | patent-ru | 2026-09-02 |
```

Бюджет индекса: **60 строк**. На 61-й — не расширять, а разделить на
`INDEX.md` (оглавление фасетов) + `counterparties/INDEX.md` и т.д., и
читать только нужный фасет. 60 строк по 140 символов ≈ 8 КБ ≈ ~2–3 тыс.
токенов — сопоставимо с одним `references/*.md`, и это потолок, а не
траектория.

### 4.3 Полоса A — элемент очереди

`queue/<skill>.md`. Шапка файла — дословно, она несёт главное ограничение:

```markdown
# Очередь на внесение в реестр — patent-ru

**Это не источник для ответа.** Ни одна строка отсюда не цитируется
пользователю как норма и не используется вместо живого поиска. Назначение
файла — не искать одно и то же в третий раз вслепую и не забыть внести
накопленное в `references/norms-registry*.md`. Норма нужна в ответе —
живой поиск заново, по «Протоколу пробела в базе».

---

## A-patent-1363-poshlina

- **о чём:** размер и срок пошлины за поддержание патента в силе, ст.1363 ГК РФ
- **спрашивали:** 2026-09-02, 2026-09-14 (2 раза)
- **живая проверка:** `python scripts/rospatent.py ...` → 2026-09-02,
  прочитан текст статьи на rospatent.gov.ru, вернулась дословная строка
  о пошлине (см. `docs/dispatch-history.md` за эту дату)
- **подтип AD HOC:** прочитан текст  ← (существование/маршрут | прочитан текст)
- **класс по §1 конвенции:** часто меняется (постановления Правительства)
- **гейт 1 (текст прочитан):** пройден 2026-09-02
- **гейт 2 (норма стабильна для заморозки):** НЕ пройден — часто меняется
- **вывод:** дословно не замораживать даже в реестре; кандидат на запись-парафраз со ссылкой и инструкцией проверки
- **статус:** в очереди
```

Статусы: `в очереди` → `предложено владельцу <дата>` → `внесено в реестр
<id записи> <дата>` (после этого элемент **переносится в `archive/`**) или
`отклонено (<причина>) <дата>`.

Срока годности у элемента очереди нет и не нужно — просроченный пункт
списка дел безвреден, потому что его никто не цитирует. Это и есть выигрыш
от схлопывания полосы A в очередь (§6).

## 5. Открытый вопрос: полоса B — общая или по скиллам

**Рекомендация: общая база, разбитая по сущностям (контрагент / дело /
приём), а не по скиллам. Полоса A — по скиллам, по одному файлу.**

Обоснование, по порядку убывания веса:

1. **Знание полосы B — свойство бизнеса владельца, а не свойство скилла.**
   «ООО „Стройпоставка“ всегда правит п.7» — это факт об ООО
   «Стройпоставка». Он не принадлежит `legal-ru` больше, чем
   `arbitrazh-ru`. Разложить его по скиллам — значит выбрать
   классификацию, которой у факта нет, и потом жить с последствиями
   выбора.
2. **Сквозной сценарий — не бонус, а основной режим.** Подряд → претензия
   → арбитраж проходит через `legal-ru` (подряд), `legal-ru`
   (досудебка) и `arbitrazh-ru`. При разбиении по скиллам одна и та же
   карточка пишется трижды, три копии расходятся, и та, что читает
   `arbitrazh-ru` в момент подачи иска, оказывается самой старой.
3. **Аргумент «честнее держит независимость плагинов» не проходит
   проверку.** Независимость в этой семье — про код и установку, и она
   сформулирована ровно так: `docs/norms-verification-convention.md` §8 —
   «There is no shared library and none is planned». Общий каталог с
   markdown-файлами в `$HOME` — не библиотека и не зависимость сборки.
   Скилл, установленный в одиночку, находит либо пустой `practice/`, либо
   индекс с меньшим числом строк, и работает ровно так же. Ни один плагин
   не начинает требовать другого.
4. **Разбиение по сущностям даёт то, ради чего хотели разбиение по
   скиллам, и ещё цену чтения в придачу.** Скилл читает `INDEX.md` и
   открывает только карточки, чьи ключевые слова совпали; колонка
   `скиллы` — фильтр, а не разграничение владения. Стоимость чтения растёт
   от числа релевантных карточек, а не от числа установленных скиллов.

Почему полоса A при этом **по скиллам**: элемент очереди адресован
конкретному `references/norms-registry*.md` конкретного репозитория, и
конвенция §5 уже задаёт разбиение реестров («One branch → one registry
file»). Общая очередь на четыре скилла — это список, из которого никто не
знает, что брать в свой коммит.

## 6. Почему полоса A — очередь, а не база (главное решение документа)

Бриф допускает вывод «строить надо радикально меньше». Вот он, с разбором.

Если полоса A — база знаний, то её запись:

1. **дублирует то, для чего уже есть место.** У каждого скилла есть
   `references/norms-registry*.md` с отработанным форматом, словарём
   статусов и проверенным прецедентом двойной сверки (§2 `patent-ru`).
   Локальная копия — второй реестр с более слабым провенансом, который
   никто не ревьюил и который нельзя показать никому, кроме себя.
2. **требует правила устаревания** — и §9 утверждений ведущей сессии тут
   абсолютно прав: храповик без срока годности хуже сегодняшнего честного
   «не проверено». Но срок годности означает, что через N месяцев запись
   надо либо пересверять живьём, либо разжаловать. Пересверка живьём — это
   ровно то действие, которое скилл и так выполняет по «Протоколу
   пробела». То есть база платит за то, чтобы отложить работу, которую всё
   равно придётся сделать, и в промежутке говорит уверенным голосом.
3. **несёт весь риск самоотравления семьи.** Записанная выдержка из нормы,
   которая на самом деле пересказ по памяти, — это тот самый провал, ради
   борьбы с которым построена вся конвенция. RED-прогон `arbitrazh-ru`
   дал живой пример: модель без скилла назвала «Постановление Пленума ВАС
   РФ от 12.10.2006 № 55» без пометки непроверенности
   (`docs/PROJECT-JOURNAL.md`). Дать этому механизм записи на диск —
   означает превратить разовую ошибку в постоянную.

Что при этом теряется, если полосу A схлопнуть в очередь: скилл не сможет
ответить на повторный вопрос без повторного живого поиска. Это и есть вся
потеря, и она мнимая — живой поиск занимает один вызов скрипта, а его
результат **обязателен по «Протоколу пробела» в любом случае**, независимо
от того, есть локальная запись или нет.

Что при этом приобретается: повторяемость вопроса становится **видимой**
(«спрашивали 3 раза»), и это единственный сигнал, который реально нужен для
решения «пора внести в реестр». Промоушен из очереди в реестр остаётся
действием человека с коммитом — ровно как и весь остальной провенанс в этой
семье.

**Два гейта остаются, но перемещаются.** Они больше не охраняют вход в
локальную базу — они заполняются в элементе очереди и охраняют вход в
настоящий реестр:

- **Гейт 1 — текст реально прочитан.** Переиспользуется, без изменений,
  различение подтипов AD HOC из §7 конвенции: подтверждение существования
  и маршрута (`by-title` в `legal-ru`, `status` в `gost-ed-mashiny`)
  **гейт 1 не проходит**; чтение самого текста источника
  (живой read `rospatent.gov.ru` по ст.1363 в `patent-ru`) — проходит.
  Элемент очереди обязан назвать подтип явно.
- **Гейт 2 — норма достаточно стабильна, чтобы её замораживать.**
  Переиспользуется решающее правило §1 конвенции, поштучно, не на файл:
  редко меняется + два источника → дословная выдержка допустима; часто
  меняется или один источник → только парафраз со ссылкой и инструкцией
  проверки; класс `PROCEDURAL DETAIL` — **никогда не замораживается**, ни
  дословно, ни локально.

## 7. Путь чтения

Один вход, три уровня, дальше первого уровня ходят не всегда.

**Уровень 0 — `SKILL.md`, грузится всегда.** Одна строка в таблице
маршрутизации: «Задача касается конкретного контрагента, дела, заявки или
уже применявшегося приёма → сначала `~/.ru-legal-skills/practice/INDEX.md`».

**Уровень 1 — `practice/INDEX.md`, ≤60 строк.** Читается **до** загрузки
ветки `references/*.md`, чтобы знание о деле успело повлиять на выбор
ветки. Если каталога нет — это не ошибка и не повод что-то сообщать
пользователю: скилл работает ровно как сегодня. Отсутствие базы — штатное
состояние первого дня.

**Уровень 2 — карточки, чьи ключевые слова совпали.** Открывать **не более
трёх** за раз. Если совпало больше — показать пользователю список
совпадений и спросить, а не дочитывать всё подряд.

**Приоритет при конфликте, жёстко:**

- О **норме** — реестр скилла всегда старше карточки. Карточка не может
  сказать, что говорит закон; она может сказать только, что произошло.
- О **практике владельца** — карточка старше общих соображений модели.
- Карточка против карточки — **не разрешать молча**. Показать обе с датами
  и источниками и спросить. Молчаливое разрешение конфликта — это способ,
  которым нижний слой знания незаметно переписывает верхний.

Полоса A **в пути чтения не участвует**. `queue/*.md` читается только
процедурой обслуживания и по прямой просьбе пользователя («что там
накопилось»).

## 8. Что появляется в `SKILL.md`: бюджет 10 строк

**Число: 10 строк, жёсткий потолок 12.** Из них 1 — строка таблицы
маршрутизации, 9 — компактный блок.

Обоснование числа, а не ощущения:

- `SKILL.md` грузится при каждой активации. Текущие размеры: `patent-ru`
  131, `legal-ru` 136, `arbitrazh-ru` 143, `gost-ed-mashiny` 195 строк.
  10 строк — это +5…+8%.
- Сравнение с прецедентом той же семьи: «Протокол пробела в базе» стоит
  ~30–70 строк в разных скиллах и оправдывает это тем, что срабатывает
  **на каждом вопросе** — он стоит до обращения к реестру. Слой роста
  срабатывает на заметно меньшей доле задач (только там, где есть
  сущность или накопленный приём). Постоянная цена должна быть
  пропорционально меньше — отсюда порядок «единицы строк», а не «десятки».
- Всё, что не влезло, идёт в два места, по уже существующему соглашению
  семьи (`references/` — для агента по требованию, `docs/` — для человека
  и сопровождающего):
  - `references/practice-write.md` (~40–60 строк) — форматы §4, список
    допустимых источников, запреты. Читается **только перед первой записью
    в сессии**, то есть редко.
  - `docs/growth-layer.md` — ежемесячное обслуживание, промоушен из
    очереди в реестр, обнуление, обоснование конструкции. Агент не грузит
    это в обычной работе никогда.

Черновик блока (ровно 10 строк, для `legal-ru`; в остальных — свой список
скиллов и своё имя файла очереди):

```markdown
## Практика (локальная, вне репозитория)

`~/.ru-legal-skills/` (или `$RU_SKILLS_MEMORY`). Нет каталога — работать как обычно, молча.
- **Читать:** до загрузки ветки открыть `practice/INDEX.md`; по совпадению ключевых слов — не более трёх карточек. Индекса нет — не искать дальше.
- **Писать:** только когда пользователь сообщил факт о своей практике, дал документ или назвал реальный исход. Перед первой записью в сессии прочитать `references/practice-write.md`. Есть файл `PAUSED` — не писать.
- **Никогда не писать:** ничего, что помнит модель, а не получила извне; текст, номер, дату или сумму нормы (это реестры); ФИО, телефоны, адреса и иные ПДн физлиц.
- **Приоритет:** о норме — реестр всегда старше карточки; карточка говорит, что произошло, а не что требует закон.
- **Норма нашлась живым поиском и тема повторяется** — не записывать как знание: добавить пункт в `~/.ru-legal-skills/queue/legal-ru.md` и предложить владельцу внести запись в реестр.
```

(Плюс одна строка в таблицу маршрутизации.) Для `arbitrazh-ru`, у которого
сегодня вообще нет фразы о промоушене, последняя строка блока закрывает
этот пробел заодно.

## 9. Путь записи

**Когда агент пишет — исчерпывающий список триггеров:**

1. Пользователь сообщил факт о своей практике, контрагенте, деле или
   исходе. Признак: утверждение о том, что было, а не вопрос о том, как
   надо.
2. Пользователь дал документ, и из него следует устойчивый факт
   (кто подписант, какая редакция спорного пункта прошла, какой раздел РЭ
   приняли).
3. Стал известен реальный исход: ФИПС принял/отказал, суд принял иск,
   орган по сертификации подписал, контрагент подписал редакцию.
4. Пользователь прямо поправил агента. Записывается **поправка**, а не
   вывод из неё.
5. Живой поиск дал норму вне реестра, и тема повторяется → **только пункт
   в `queue/`**, не карточка.

Ничего другого. В частности, не триггер: агент что-то заметил; агент
сделал вывод; агенту показалось важным; в диалоге получился хороший
черновик.

**Протокол самой записи** — переиспользуется правило из
`writing-fragments/SKILL.md` (с оговоркой из §1/#3 о его статусе):

- **Перечитать файл с диска перед каждой записью.** Владелец мог править
  его руками между ходами.
- **Только дозапись** — добавить пункт в «Что известно», добавить
  карточку, добавить строку в индекс. Правка существующего текста
  владельца — только по его прямой просьбе.
- **Никогда не удалять.** Отмена — перенос в `archive/` со строкой «снято
  <дата>, причина».
- **Объявить, не спрашивать разрешения** — одна строка в ответе:
  «Записал в практику: `B-cp-strojpostavka` — <суть>. Отменить — скажите.»
  Вопрос с ожиданием ответа на каждую запись породит усталость и
  автоматическое «да», то есть человеческий гейт превратится в штамп. Для
  полосы A наоборот: внесение в реестр — **всегда** явное решение
  владельца с коммитом.

**Разрешения.**

- *Claude Code.* Каталог вне рабочего — запись будет спрашивать
  подтверждение при обычных настройках (на этой машине
  `~/.claude/settings.json` сейчас стоит `permissions.defaultMode: "auto"`,
  поэтому прямо сейчас владелец разницы, вероятно, не заметит — но
  конструкция не должна на это опираться). Нужна запись в `allow` вида
  `Read`/`Write`/`Edit` на `~/.ru-legal-skills/**`. **Точный синтаксис пути
  для абсолютного каталога в правилах файловых инструментов я не проверял
  и не выдумываю** — проверяется за одну правку `settings.json` и один
  пробный write, и это надо сделать до того, как записывать синтаксис в
  `docs/growth-layer.md`.
- *Codex.* Прочитано в `~/.codex/config.toml`: `sandbox_mode =
  "workspace-write"`, в `[sandbox_workspace_write]` только
  `network_access = true`. Запись вне рабочего каталога песочница
  заблокирует. Правка:

  ```toml
  [sandbox_workspace_write]
  network_access = true
  writable_roots = ["C:\\Users\\<user>\\.ru-legal-skills"]
  ```

  Прочитано в конфиге, **живой записью не проверялось.**

**Чего агент не имеет права писать никогда** (эти четыре — в `SKILL.md`,
не только в `references/`):

1. Ничего, чей источник — собственная память или рассуждение модели.
   Единственное правило, без которого всё остальное бессмысленно.
2. Текст нормы, номер статьи, дату редакции, срок или сумму. Для этого
   есть реестры, и у них есть статусы. Карточка полосы B ссылается на
   запись реестра по id и не пересказывает её.
3. Персональные данные физических лиц: ФИО, телефон, адрес, паспорт,
   должность конкретного человека в связке с его именем. Карточки — про
   организации и роли («главный инженер заказчика»), не про людей. У
   владельца есть ветка 152-ФЗ; заводить себе неучтённую базу ПДн этой
   конструкцией — недопустимо.
4. Содержимое, которое навредит при утечке файла: суммы по живому спору,
   переговорная позиция, оценка перспектив дела. Формулировка «что уже
   произошло» проходит, «что мы готовы уступить» — нет. Основание не
   теоретическое: у этой семьи уже есть незакрытая утечка в GitHub
   (`docs/PROJECT-JOURNAL.md`).

## 10. Как владелец смотрит, правит и обнуляет

- **Смотрит:** `~/.ru-legal-skills/practice/INDEX.md` в любом редакторе —
  одна таблица, весь объём базы виден на одном экране, пока действует
  бюджет 60 строк. Это не побочный эффект: индекс, который нельзя
  охватить взглядом, нельзя и проконтролировать.
- **Правит:** правит файл руками. Агент перечитывает перед каждой записью
  и не перезаписывает — правка переживает следующую запись агента.
- **Ставит на паузу:** создаёт пустой файл `~/.ru-legal-skills/PAUSED`.
  Скиллы продолжают читать, но не пишут ни строчки. Убрать файл —
  вернуться. Дешёвый выключатель на случай «сейчас не надо».
- **Отменяет одну запись:** говорит агенту «убери B-cp-...», агент
  переносит карточку в `archive/` и вычёркивает строку индекса. Или делает
  то же самое руками.
- **Обнуляет полностью:** удаляет каталог `practice/`. Скиллы возвращаются
  ровно к сегодняшнему поведению — никакой деградации, потому что база
  нигде не является предусловием.
- **Аудит один раз в месяц** (описан в `docs/growth-layer.md`, не в
  `SKILL.md`): grep по `Источник:` — каждый пункт каждой карточки обязан
  иметь валидный префикс; пункты без него — квартанин и разбор вручную.
  Это единственная проверка, которая ловит уже случившееся отравление.

## 11. Обновление плагина и вторая машина

**Обновление плагина.** С базой не происходит ничего: она лежит вне
версионного каталога установки (§1/#4 — Claude Code ставит в
`cache/<marketplace>/<plugin>/<version>/`, Codex в тот же путь с суффиксом
`+codex.<timestamp>`, то есть новый каталог при каждой переустановке).
Именно поэтому она там и лежит.

Что **требует** обработки при обновлении — рассинхрон полосы A: элемент
очереди, который владелец успел внести в реестр, после обновления плагина
существует дважды — как запись реестра (авторитетная) и как пункт очереди
(устаревший дубль). Правило разрешения простое и проверяемое: у пункта со
статусом `внесено в реестр <id>` при чтении проверяется, есть ли этот id в
`references/norms-registry*.md` установленной версии; есть — пункт
переносится в `archive/`. Это единственная операция сверки между базой и
деревом плагина во всей конструкции.

**Вторая машина.** База не путешествует вместе с плагином — по построению.
Три варианта, в порядке рекомендации:

1. **По умолчанию — не синхронизировать.** Две машины накапливают разное.
   Для владельца, который работает с документами в основном на одной
   машине, это честнее, чем механизм синхронизации, который однажды
   разойдётся и будет тихо отдавать старую карточку.
2. **Ручной перенос по требованию:** скопировать `practice/` целиком.
   Файлы простые, конфликтов нет, потому что перенос — это решение, а не
   фоновый процесс.
3. **`RU_SKILLS_MEMORY` на облачный каталог** (OneDrive и т.п.) — работает,
   но два предупреждения, оба обязательны к произнесению вслух: (а)
   конфликтные копии вида `INDEX (2).md` — по имени не совпадают с
   конвенцией и должны игнорироваться при чтении, а не сливаться; (б) если
   каталог ещё и в git — это карточки по живым спорам в репозитории, см.
   незакрытую утечку в `PROJECT-JOURNAL.md`. Синхронизация через git
   private-репозиторий не рекомендуется вообще.

## 12. Режимы отказа и реакция конструкции

| Режим отказа | Что делает конструкция |
|---|---|
| Каталога нет (первый день, другая машина) | Работает как сегодня, молча. Отсутствие — штатное состояние, не ошибка, пользователю не сообщается |
| `INDEX.md` есть, карточки нет (владелец удалил) | Строка индекса пропускается. **Категорически не восстанавливать содержание карточки по строке индекса** — это прямой путь к записи галлюцинации |
| Карточка есть, в индексе нет | Карточка невидима. Обнаруживается ежемесячным аудитом, чинится добавлением строки. Неприятно, но безопасно |
| Индекс вырос за 60 строк | Разделить на фасеты, читать один. Не расширять бюджет |
| В карточке пункт без валидного `Источник:` | Пункт не читается; карточка помечается пользователю как повреждённая. Это ловушка на уже случившееся отравление |
| Карточка противоречит реестру о норме | Реестр выигрывает всегда. Карточка о норме — сама по себе дефект, её в `archive/` |
| Две карточки противоречат друг другу | Не разрешать молча. Показать обе с датами и источниками, спросить владельца |
| Отравление всё-таки произошло | Ежемесячный grep по `Источник:` + правило «карточка говорит, что произошло, а не что требует закон» ограничивают радиус поражения практикой, а не правом. Полностью проблема не закрывается — см. §14 |
| Две сессии пишут одновременно | Один файл на карточку + дозапись → коллизия возможна только в `INDEX.md`, где строки независимы. Перечитывание перед записью закрывает практически |
| Владелец поправил руками, сломав формат | Разбирать терпимо: непонятная строка показывается владельцу, не домысливается |
| Песочница Codex не пускает на запись | Записи не происходит, агент говорит об этом прямо. Не пытаться писать в обход, не складывать «пока что» в рабочий каталог |
| Файл `PAUSED` на месте | Чтение работает, запись не происходит, об этом сказано одной строкой |
| Плагин обновился, пункт очереди устарел | Проверка по id записи реестра → `archive/` (§11) |
| Карточка «приём сработал» с n=1 | Раздел «Чего это НЕ значит» обязателен и не может быть пустым; ежемесячный аудит смотрит на карточки с одним наблюдением отдельно |

## 13. Что конструкция сознательно НЕ делает

- **Не учится на собственных рассуждениях.** Никогда, ни при каких
  настройках, ни в «режиме эксперта». Отключаемого варианта этого правила
  нет.
- **Не заводит локальную базу норм** (§6). Для норм есть реестры и живой
  поиск.
- **Не содержит кода.** Ни скриптов, ни индексаторов, ни векторного
  поиска, ни базы. Иначе это надо портировать в Codex и чинить в двух
  местах.
- **Не синхронизирует машины** и не делает вид, что синхронизирует.
- **Не пишет в дерево плагина и ни в один git-репозиторий по умолчанию.**
- **Не удаляет ничего.** Только `archive/`.
- **Не ставит оценок уверенности, весов и «важности».** Число, которое
  нельзя проверить, притягивает доверие, которого не заслужило. Есть
  только дата и источник.
- **Не создаёт разделяемого кода между плагинами** — §8 конвенции остаётся
  верным: это файловая конвенция, а не библиотека.
- **Не автоматизирует промоушен в реестр.** Коммит в репозиторий —
  действие человека, как и весь остальной провенанс в этой семье.
- **Не трогает `lazy-skill-library`.** Там побитово-идентичные снимки на
  закреплённых коммитах, и выученное пользователем в них не попадает
  никогда — иначе снимок перестаёт быть снимком.

## 14. Что в самом этом проекте не проверено, рискованно или может оказаться неверным

**Не проверено экспериментом:**

1. Поведение постороннего файла при обновлении плагина. Раскладка каталогов
   установки прочитана на этой машине в обоих рантаймах и версионирование
   подтверждено, но эксперимента «положить файл → обновить → посмотреть» я
   не ставил. Плагины этой семьи на этой машине вообще не установлены —
   наблюдение снято с `agent-bridges`. Политику `.last_inuse_sweep` не
   выяснял: возможно, старые версии со временем удаляются, и тогда файл в
   дереве плагина не «остаётся в стороне», а именно пропадает. На решение
   это не влияет (в дерево плагина не пишем в любом случае), на
   формулировку в `docs/` — влияет.
2. Точный синтаксис правила разрешения в `settings.json` Claude Code для
   абсолютного каталога вне проекта. Намеренно не написан — проверяется за
   одну правку.
3. `writable_roots` для Codex: конфиг прочитан, правка выведена из него,
   живой записью не проверена.
4. Насколько надёжно Codex выполняет инструкцию «прочитай этот файл в
   начале задачи». В Claude Code это работает; у семьи есть опыт, что
   рантаймы расходятся в неожиданных местах (история с `"source":
   "github"`, `PROJECT-JOURNAL.md` — Codex молча показывал ноль плагинов).
   До проверки нельзя утверждать, что слой роста одинаково живой в обоих.
5. Бюджеты — 60 строк индекса, 10 строк `SKILL.md`, 3 карточки за раз —
   инженерные оценки, а не измерения. Проверяются только на реальной базе
   через пару месяцев.

**Риски конструкции:**

6. **Главный риск — усталость подтверждения.** Схема держится на том, что
   владелец читает строку «Записал в практику: …» и иногда говорит «нет».
   Если он перестанет читать, человеческий гейт превратится в штамп, и
   отравление пойдёт через человека, который не смотрит. Смягчение —
   ежемесячный аудит и маленький объём базы; устранить нельзя.
7. **Выжившая выборка в полосе B.** «Эта формулировка прошла ФИПС» —
   одно наблюдение. Раздел «Чего это НЕ значит» — противоядие слабое: его
   пишет та же модель, что и саму карточку.
8. **Граница «норма / практика» на письме тоньше, чем на бумаге.** «Суд
   принял иск с таким приложением» — практика. «Суд требует такое
   приложение» — норма, замаскированная под практику. Этот класс ошибки
   проходит все механические проверки, включая grep по `Источник:`. Это
   самая вероятная точка отказа всей конструкции, и у меня нет для неё
   механического решения — только формулировка правила и аудит.
9. **Персональные данные — риск, который я добавил, а не нашёл в брифе.**
   Карточки по контрагентам естественно тянут ФИО и контакты. Запрет
   записан, но он держится на дисциплине агента в момент записи.
10. **Может оказаться, что строить не надо вообще.** Если за месяц работы
    полоса B наберёт 5–7 карточек, вся конструкция не окупит даже своих 10
    строк в `SKILL.md`. Разумный способ это выяснить, не строя: **месяц
    вести `practice/INDEX.md` вручную** — владелец сам дописывает строку,
    когда ловит себя на объяснении агенту одного и того же. Пустой или
    почти пустой индекс через месяц — прямой ответ «не строить», и он
    стоит ноль строк кода и ноль строк `SKILL.md`. Это моя рекомендация по
    порядку действий: сначала месяц ручного индекса, потом решение.
11. **Рекомендация «общая база B» может оказаться неверной**, если
    владелец однажды начнёт ставить эти плагины кому-то ещё или работать
    по нескольким несвязанным бизнесам. Тогда «свойство бизнеса» перестаёт
    быть единственным — понадобится разбиение по проекту, а не по скиллу.
    Миграция дешёвая (переменная `RU_SKILLS_MEMORY` на другой каталог), но
    это надо знать заранее, а не обнаружить.
12. **Ничего из этого не протестировано RED→GREEN**, а в этой семье
    незатестированная конструкция по определению не считается работающей
    (`docs/review-checklist.md`, «Testing status — track it, don't
    assume it»). Минимальный набор сценариев до внедрения: (а) агент
    пытается записать собственный вывод — должен отказаться; (б) агент
    пытается записать норму в карточку полосы B — должен отправить в
    очередь; (в) карточка противоречит реестру — реестр должен выиграть;
    (г) каталога нет — скилл должен отработать молча, ничего не сообщая.
